# Schema Authoring Guide

Each subdirectory in `schemas/` is a **schema bundle** — a self-contained configuration package for a specific HDF5 dataset format. This guide explains how to create a schema bundle for your custom robot dataset.

## Schema Bundle Anatomy

```
schemas/
└── your_schema_name/
    ├── schema.json      # HDF5 structure reference (auto-generated)
    ├── mapping.yaml     # HDF5 → LeRobot field mapping (required)
    └── hooks.py         # Custom conversion logic (optional)
```

### schema.json — HDF5 Structure Reference

Auto-generated by `validate_schema.py`. Documents every group and dataset in your HDF5 files: paths, data types, dimensionality, and shapes. The converter uses this to:

- Calculate feature dimensions (how many columns to expect when concatenating observation/action components)
- Generate feature names for `info.json`
- Validate that your mapping paths exist

**You should not edit this file by hand.** Regenerate it whenever your HDF5 format changes.

Example entry:

```json
{
  "reference_file": "episode_001.hdf5",
  "groups": ["/action", "/action/joint_pos", "/observation", ...],
  "datasets": {
    "/action/joint_pos/left": {
      "dtype_kind": "f",
      "dtype_itemsize": 4,
      "ndims": 2,
      "shape": [553, 6]
    }
  }
}
```

### mapping.yaml — Field Mapping Configuration

The core configuration file. Tells the converter how to read your HDF5 data and map it to LeRobot features. This file is **required** for every schema bundle.

Sections:
- `dataset` — Metadata: repo ID, robot type, FPS, chunk size
- `observation_state` — HDF5 paths to concatenate into `observation.state`
- `action` — HDF5 paths to concatenate into `action`
- `extra_observations` — Additional per-frame numeric features
- `images` — Camera definitions, compression format, video encoding settings
- `language_instructions` — How to extract task/language descriptions
- `filtering` — Episode skip conditions

See the root [README.md](../README.md#configuration-reference-mappingyaml) for a complete field reference.

### hooks.py — Custom Conversion Logic (Optional)

A Python file with a `Hooks` class that overrides specific conversion behaviors. Only define the methods you need — missing methods use no-op defaults.

See the root [README.md](../README.md#hook-system) for all available hook methods.

## Steps to Create a New Schema Bundle

### Step 1: Generate the schema

Run `validate_schema.py` on a reference HDF5 file from your dataset:

```bash
python validate_schema.py /path/to/your/hdf5_files/ --output-dir schemas/your_schema_name/
```

This produces `schema.json` with all groups, datasets, dtypes, and shapes. It also generates a `validation_report.md` showing which files in the directory match the reference structure.

If you want to use a specific file as the reference (recommended — pick a high-quality, complete episode):

```bash
python validate_schema.py /path/to/your/hdf5_files/ \
    --reference best_episode.hdf5 \
    --output-dir schemas/your_schema_name/
```

**Review the validation report.** If many files have missing datasets or dtype mismatches, investigate before proceeding. The converter will fail on files that don't match the expected structure unless you handle the inconsistency in hooks.

### Step 2: Inspect your HDF5 structure

Before writing the mapping, explore your HDF5 files to understand what data is available:

```python
import h5py

with h5py.File("/path/to/episode.hdf5", "r") as f:
    def show(name, obj):
        if isinstance(obj, h5py.Dataset):
            print(f"  {name}: shape={obj.shape}, dtype={obj.dtype}")
        else:
            print(f"  {name}/ (group)")
    f.visititems(show)
```

Identify:
- Which datasets hold joint positions, velocities, or other state observations
- Which datasets hold actions (commanded targets)
- Where images are stored and whether they're compressed
- Where FPS/frequency metadata lives
- Whether task or language information exists

### Step 3: Create the mapping file

Copy an existing mapping as a starting point:

```bash
cp schemas/picknplace/mapping.yaml schemas/your_schema_name/mapping.yaml
```

Edit each section to match your HDF5 structure. Here's a minimal mapping for a single-arm robot:

```yaml
dataset:
  repo_id: "my_org/my_single_arm_dataset"
  robot_type: "single_arm_6dof"
  codebase_version: "v2.1"
  chunks_size: 1000
  fps:
    source: "fixed"
    fixed_value: 30

observation_state:
  components:
    - hdf5_path: "/observations/joint_positions"
      names_prefix: "joint"
    - hdf5_path: "/observations/gripper_position"
      names_prefix: "gripper"

action:
  components:
    - hdf5_path: "/actions/joint_positions"
      names_prefix: "joint"
    - hdf5_path: "/actions/gripper_position"
      names_prefix: "gripper"

images:
  compressed: false
  raw_height: 480
  raw_width: 640
  raw_channels: 3
  cameras:
    - key: "wrist"
      hdf5_path: "/observations/images/wrist_cam"
  video_codec: "libx264"
  video_pix_fmt: "yuv420p"
  video_crf: 23

language_instructions:
  source: "fixed"
  fixed:
    instruction: "perform the manipulation task"
  per_frame: false
```

#### Key decisions when writing your mapping

**Observation/action component order:** The components list defines the concatenation order. `observation.state` is built by reading each component's HDF5 dataset and horizontally stacking them. Document the order clearly — downstream code depends on knowing which indices correspond to which joints.

**Slicing columns:** If a dataset has shape `[T, 7]` but you only want the first 6 columns (e.g., drop a redundant gripper dimension), use `slice: [0, 6]`.

**Compressed vs raw images:**
- **Compressed** (`compressed: true`): Each row in the image HDF5 dataset is a byte array containing JPEG/PNG data followed by zero-padding. A separate `compressed_len_path` dataset stores the actual byte length per frame per camera (shape `[num_cameras, T]`). The `compressed_len_index` for each camera indicates its row in this array.
- **Raw** (`compressed: false`): Each row is a flat array of `raw_height * raw_width * raw_channels` uint8 values. The converter reshapes it to `[H, W, C]`.

**FPS source:**
- `"fixed"` — Use when all episodes have the same fixed frame rate and it's not stored in the HDF5 file.
- `"hdf5"` — Use when FPS is stored as a scalar value in the HDF5 file (reads from the first episode file).

### Step 4: (Optional) Add custom hooks

If your conversion needs logic that YAML configuration can't express, create `hooks.py` in your schema bundle directory:

```python
# schemas/your_schema_name/hooks.py

class Hooks:
    def filter_episode(self, h5f, mapping):
        """Return False to skip this episode."""
        # Example: skip if a quality score is too low
        if "/metadata/quality_score" in h5f:
            if float(h5f["/metadata/quality_score"][()]) < 0.5:
                return False
        return True

    def extract_language_instructions(self, h5f, num_frames, lang_cfg,
                                       episode_id, external_instructions):
        """Return list[str] of length num_frames, or None to use built-in logic."""
        return None  # Use YAML-configured strategy

    def transform_observation_state(self, obs, h5f, mapping):
        """Post-process observation array [T, D] before writing."""
        return obs

    def transform_action(self, action, h5f, mapping):
        """Post-process action array [T, D] before writing."""
        return action

    def transform_frame(self, frame, cam_key):
        """Post-process image frame (HWC uint8) before video encoding."""
        return frame

    def extra_parquet_columns(self, h5f, num_frames, mapping):
        """Return dict of extra columns to add to parquet. {name: [values]}"""
        return {}
```

Only define the methods you need — missing methods use no-op defaults.

### Step 5: Test with a single episode

Before running the full conversion, test with a small subset to catch configuration errors quickly:

```bash
# Create a test directory with just one or two HDF5 files
mkdir /tmp/test_hdf5
cp /path/to/one_episode.hdf5 /tmp/test_hdf5/

# Run conversion on the test set
hdf5-lerobot convert \
    --schema-name your_schema_name \
    --hdf5-dir /tmp/test_hdf5/ \
    --output-dir /tmp/test_output/ \
    --log-level DEBUG

# Validate the output
python validate_lerobot_dataset.py /tmp/test_output/
```

Use `--log-level DEBUG` to see detailed information about which episodes are being processed, skipped, and why.

**What to check in the test output:**
- Does `meta/info.json` have the correct feature dimensions?
- Do the feature names in `info.json` match your expectations?
- Open a Parquet file to verify the data looks correct:

```python
import pandas as pd
df = pd.read_parquet("/tmp/test_output/data/chunk-000/episode_000000.parquet")
print(df.columns.tolist())
print(df.head())
print(f"observation.state dim: {len(df['observation.state'].iloc[0])}")
print(f"action dim: {len(df['action'].iloc[0])}")
```

- Check that video files play correctly:

```bash
ffplay /tmp/test_output/videos/chunk-000/observation.images.wrist/episode_000000.mp4
```

### Step 6: Run the full conversion

```bash
hdf5-lerobot convert \
    --schema-name your_schema_name \
    --hdf5-dir /path/to/hdf5_files/ \
    --output-dir /path/to/output/
```

### Step 7: Validate the output

```bash
python validate_lerobot_dataset.py /path/to/output/
```

## Hooks Deep Dive

### Filtering by quality or metadata

```python
class Hooks:
    def filter_episode(self, h5f, mapping):
        # Skip episodes from a specific collection session
        if "/metadata/session_id" in h5f:
            session = h5f["/metadata/session_id"][()].decode("utf-8")
            if session in ("debug_session", "calibration_run"):
                return False

        # Skip episodes where the robot hit a joint limit
        if "/metadata/joint_limit_violation" in h5f:
            if bool(h5f["/metadata/joint_limit_violation"][()]):
                return False

        return True
```

### Normalizing observations

```python
import numpy as np

class Hooks:
    # Joint limits for a 6-DOF arm + 1-DOF gripper
    JOINT_LIMITS = np.array([3.14, 2.09, 3.14, 2.09, 3.14, 2.09, 0.04])

    def transform_observation_state(self, obs, h5f, mapping):
        # Normalize to [-1, 1] using known joint limits
        obs[:, :7] = obs[:, :7] / self.JOINT_LIMITS
        return obs

    def transform_action(self, action, h5f, mapping):
        # Apply the same normalization to actions
        action[:, :7] = action[:, :7] / self.JOINT_LIMITS
        return action
```

### Cropping or resizing images per camera

```python
import numpy as np

class Hooks:
    def transform_frame(self, frame, cam_key):
        if cam_key == "overhead":
            # Crop to center region (remove borders with robot structure)
            h, w = frame.shape[:2]
            frame = frame[50:h-50, 100:w-100]
        elif cam_key == "wrist":
            # The wrist camera has a fisheye lens — crop center 60%
            h, w = frame.shape[:2]
            mh, mw = int(h * 0.2), int(w * 0.2)
            frame = frame[mh:h-mh, mw:w-mw]
        return frame
```

### Adding reward and success columns

```python
class Hooks:
    def extra_parquet_columns(self, h5f, num_frames, mapping):
        columns = {}

        # Add per-frame rewards
        if "/labels/rewards" in h5f:
            rewards = h5f["/labels/rewards"][:num_frames].tolist()
            columns["reward"] = rewards

        # Add binary success flag
        if "/labels/task_done" in h5f:
            task_done = h5f["/labels/task_done"][:num_frames]
            columns["success"] = [bool(v) for v in task_done]

        # Add a grasp detection signal
        if "/observation/gripper_force" in h5f:
            forces = h5f["/observation/gripper_force"][:num_frames]
            columns["is_grasping"] = [bool(f > 0.5) for f in forces]

        return columns
```

### Custom language instruction logic

```python
class Hooks:
    def extract_language_instructions(self, h5f, num_frames, lang_cfg,
                                       episode_id, external_instructions):
        # Combine task name and object name from metadata
        task = h5f["/metadata/task_name"][()].decode("utf-8")
        obj = h5f["/metadata/object_name"][()].decode("utf-8")
        color = h5f.attrs.get("object_color", b"unknown").decode("utf-8")
        instruction = f"{task} the {color} {obj}"
        return [instruction] * num_frames
```

## Worked Example: Single-Arm Pick-and-Place Robot

Let's walk through creating a schema bundle for a hypothetical single-arm robot with the following HDF5 structure:

```
/joint_positions         [T, 6]   float32    # 6-DOF arm joint angles
/joint_velocities        [T, 6]   float32    # Joint velocities
/gripper_state           [T, 1]   float32    # Gripper open/close
/target_joint_positions  [T, 6]   float32    # Commanded joint angles
/target_gripper          [T, 1]   float32    # Commanded gripper
/camera/front            [T, 307200] uint8   # 480x640 raw RGB flattened
/camera/wrist            [T, 307200] uint8   # 480x640 raw RGB flattened
/frequency               ()        float64   # 15 Hz
/task_label              ()        bytes      # "pick red cube"
```

#### 1. Generate schema

```bash
python validate_schema.py /data/single_arm_episodes/ --output-dir schemas/single_arm/
```

#### 2. Create mapping.yaml

```yaml
dataset:
  repo_id: "my_lab/single_arm_pick_place"
  robot_type: "single_arm_6dof"
  codebase_version: "v2.1"
  chunks_size: 1000
  fps:
    source: "hdf5"
    hdf5_path: "/frequency"

observation_state:
  components:
    - hdf5_path: "/joint_positions"
      names_prefix: "joint_pos"
    - hdf5_path: "/joint_velocities"
      names_prefix: "joint_vel"
    - hdf5_path: "/gripper_state"
      names_prefix: "gripper"

action:
  components:
    - hdf5_path: "/target_joint_positions"
      names_prefix: "joint_pos"
    - hdf5_path: "/target_gripper"
      names_prefix: "gripper"

images:
  compressed: false
  raw_height: 480
  raw_width: 640
  raw_channels: 3
  cameras:
    - key: "front"
      hdf5_path: "/camera/front"
    - key: "wrist"
      hdf5_path: "/camera/wrist"
  video_codec: "libx264"
  video_pix_fmt: "yuv420p"
  video_crf: 23

language_instructions:
  source: "hdf5_attribute"
  hdf5_attribute:
    group: "/"
    attribute: "task_label"
  per_frame: true
```

This produces:
- `observation.state` = `[T, 13]` (6 joint pos + 6 joint vel + 1 gripper)
- `action` = `[T, 7]` (6 target joint pos + 1 target gripper)
- Two cameras: `observation.images.front` and `observation.images.wrist`
- Per-frame `language_instruction` column from the `task_label` attribute

#### 3. Convert

```bash
hdf5-lerobot convert \
    --schema-name single_arm \
    --hdf5-dir /data/single_arm_episodes/ \
    --output-dir /data/single_arm_lerobot/
```

#### 4. Validate

```bash
python validate_lerobot_dataset.py /data/single_arm_lerobot/
```

## Pre-Conversion Checklist

Before running the full conversion, verify:

- [ ] `schema.json` is generated and validation report shows acceptable results
- [ ] All `hdf5_path` entries in mapping.yaml exist in schema.json
- [ ] `observation_state` components are in the correct concatenation order
- [ ] `action` components are in the correct concatenation order
- [ ] `names_prefix` values are unique and descriptive
- [ ] FPS source is correctly configured (test: open an HDF5 file and check the value)
- [ ] Image configuration matches your format (compressed vs raw, correct dimensions)
- [ ] `compressed_len_index` values are correct for each camera (0-indexed)
- [ ] Language instruction strategy is configured and tested
- [ ] Filtering rules won't exclude all episodes (check with `--log-level DEBUG`)
- [ ] Test conversion works on 1-2 episodes
- [ ] Output Parquet files have correct column dimensions
- [ ] Output videos play correctly and show the expected camera views
- [ ] `validate_lerobot_dataset.py` passes on the test output
